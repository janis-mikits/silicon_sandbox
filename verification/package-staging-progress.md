# Package staging progress

`OneBitPackageStager.Prepare` now rejects a stale configuration draft and builds a coherent proposed world snapshot containing the new exact fixed module version and its first free inventory slot. It leaves the source world, live session, global library, and present inventory untouched. Its result is **not** a published package: V1 encoding, strict validation, recoverable file publication, and the UI Confirm action must all succeed before the game exposes that inventory item.

After the recoverable publisher verifies and commits all three prepared files, it returns a receipt naming the exact world/version and content hashes. `OneBitWorldContext.ApplyDurablyPublishedPackage` requires that receipt and the unchanged authored revision before it registers the version and swaps in the new inventory. It does not rebuild the live circuit: a test advances the world clock and toggles a source before applying a test publication, then checks that simulation time, running clock, source state, and world revision stay unchanged. The test publication uses opaque repository-local bytes to exercise the receipt boundary; it is not a V1 semantic save test.

Independent tests verify the source world and inventory remain unchanged, the copied module gets independent authored IDs, the proposed inventory names the exact version, and a stale draft cannot publish. Offline verification after the receipt integration: the repository-local Edit Mode runner command in [benchmark instrumentation](benchmark-instrumentation-progress.md) passed 157 tests with zero failures; the offline Play Mode source compilation succeeded with zero warnings/errors. These are supplemental checks, not a Unity Test Runner result. Unity Play Mode and V1 durable package publication remain unrun/incomplete.

Files changed in this step: `OneBitWorldSession.cs`, `OneBitWorldContext.cs`, `AtomicPackageFilePublisher.cs`, `OneBitPackageStagerTests.cs`, and this report. The earlier staging step added `OneBitPackageStager.cs` and its tests.
